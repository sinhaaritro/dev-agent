Agent Workflow Protocol

Visual summary of SPEC-002 — the structured multi-phase lifecycle for complex task execution.

🔄 Core Workflow Lifecycle

1 Stage 1: Pre-coding
→
2 Stage 2: Coding
→
3 Stage 3: Post-coding
1 Analysis, discovery, Socratic trade-off alignment, plan design, and the Approval Gate. 2 Systematic implementation of approved tasks in task.md under clean code guidelines. 3 Automated validation (tests, builds, lints) and delivering a complete walkthrough report.
The agent requires explicit human approval to transition from Stage 1 to Stage 2. Session recovery and interrupts are handled by background protocols.

🗺️ Lifecycle Phase Details

Stage 1: Pre-coding Phase @architect, @legacy-analyst, @security-reviewer PLAN / BRAINSTORM → Full spec
1. Discovery→ 2. Socratic Alignment→ 3. Design Plan→
4. Approval Gate ⛔ Human Sign-off
Step Phase Action
1 Analysis & Discovery: Scan codebase, memory mappings, and active handoffs. Do not modify files.
2 Socratic Gate: Flag ambiguous requirements. Propose options and trade-offs tables for human alignment.
3 Plan & Solution Design: Scaffold implementation_plan-{slug}.md and task-{slug}.md detailing changes.
4 Approval Gate: Halt execution. Transition to Stage 2 only when the human explicitly commands to proceed.
Activated By:
  • COMPLEX CODE Path: Step 5 dispatches to Stage 1.
  • DESIGN/UI Path: Steps 5-8 iteratively prototype and plan within Stage 1.
Stage 2: Coding Phase @frontend-developer, @backend-developer, @document-writer IMPLEMENT → Full spec
1. Initialize task.md→ 2. Work Milestones→ 3. Clean Code Adherence
Step Phase Action
1 Initialize task.md Checklist: Establish granular task list tracking in the workspace.
2 Work Milestones: Modify files sequentially. Maintain status indicators ([/] in-progress, [x] complete).
3 Clean Code Adherence: Respect software engineering best practices (KISS, modularity, docs preservation).
Activated By:
  • Entered automatically upon Stage 1 design approval (proceeding to code).
Stage 3: Post-coding Phase @qa-tester, @security-tester, @seo-verifier REVIEW / DEBUG → Full spec
1. Automated Verification→ 2. Deliver Walkthrough
Step Phase Action
1 Automated Verification: Run linters, compilers, and test suites (e.g. task verify) to prove changes work.
2 Deliver Walkthrough: Generate walkthrough-{slug}.md with Change Registry, logs, and UI recordings.
Activated By:
  • Entered automatically after Stage 2 checklist completion. Also used by bug-fix and simple-code paths for inline verification.
Session Resume Protocol @orchestrator Stateless Recovery → Full spec
1. Worktree Check→ 2. Scan docs/plans/→ 3. Assess State→ 4. Announce Banner
Step Phase Action
1 Worktree Check: Detect if session workspace is in a worktree. Ingest subagent_dispatch.md if present.
2 Scan docs/plans/: Search for active plans and checklists in the workspace folders.
3 Determine State: Evaluate approvals and task progress to resolve the active execution stage.
4 Announce State: Output a visible session resume notification console banner.
Precedence:
  • Runs before request classification. If active plans are found, the classifier is bypassed to maintain state.
Escape Hatch Rule All Personas TEACH / REVIEW → Full spec
1. Interruption→ 2. Bypass Constraints→ 3. Separate Artifact→ 4. Return Prompt
Step Phase Action
1 Interruption: Human raises off-topic, exploratory, or teaching question mid-lifecycle.
2 Bypass Constraints: Shift temporarily to TEACH or REVIEW mode to answer.
3 Separate Artifacts: Direct analytical output to a scratchpad file (do not write into the active plan).
4 Return Prompt: End response with a link reminding the user of the active plan state.
Routing Interaction:
  • Temporarily yields control back to the request classifier to resolve off-topic queries, then returns user to active plan.

📊 Workflow-Driven vs. Traditional Execution

Execution Phase Workflow-Driven Agent (SPEC-002) Traditional IDE Assistant
Planning & Design Structured discovery, trade-off options, and explicit sign-off gates. Jumps directly to coding without planning or verifying requirements.
Implementation Granular tracking via task.md checklist. Sequential changes. Edits multiple files haphazardly. Prone to stray edits and code churn.
Verification Runs tests, compilers, and linters to prove correctness before ship. Stops after typing code. Fails to verify compile errors or test failures.
Session Interrupts Bypasses constraints cleanly to answer, saving scratch files, then returns to plan. Loses context or gets distracted, derailing the main task implementation.
Handoff & Resume Restores active plan state automatically on boot via file scans. Starts from a blank state. Relies on human to re-explain progress.
